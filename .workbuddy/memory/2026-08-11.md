## qq-codex-bridge 智能调度模块剖析

- 用户请求：详细剖析智能调度模块（任务接收、资源评估、策略决策、分发调度、端到端链路、调度算法、状态机、并发控制）
- 项目调度分两条独立链路：
  1. **对话链路**：`BridgeOrchestrator`（`packages/orchestrator/src/bridge-orchestrator.ts`）—— 接收 QQ/微信/飞书入站、绑定 Codex 会话、流式回传
  2. **推送链路**：`PushOrchestrator` + `PushWorker`（`packages/push/src/`）—— HTTP API/MCP 入站、SQLite 持久化队列、状态机、重试、多渠道出站
- 关键架构决策：
  - 端口契约 (`packages/ports/src/`) 解耦具体实现（`PushRepositoryPort` / `PushEgressPort` / `ConversationProviderPort`）
  - `SqlitePushRepository` 用 SQLite + `BEGIN IMMEDIATE` 事务实现乐观互斥
  - Push Worker 单进程 tick 循环 + `recoverStale` 容错（300s 阈值）
  - `withSessionLock` 双层：进程内 promise tail queue + SQLite row lock
